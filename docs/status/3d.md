# 3D rendering status

WIP. Unchanged glxgears, poulscube and glxheads render through the
[submission engine](../kernel/execution.md#p3-engine) in Xorg with the poulsback DDX.
The [Mesa screen](mesa.md) is available; complete API coverage and the everyday
desktop remain open.

## Working and checked

- **GPU vertex shading:** accepted shaders run on the USSE, with
  constants per draw and VBO/IBO data read in place. glxgears, poulscube and
  the vertex fixtures match the CPU vertex path. The backend
  accepts a bounded F32 arithmetic subset; Mesa's draw module still handles
  refused shaders and draws
  ([GPU vertex shading](../graphics.md#gpu-vertex-shading),
  [GPU contracts](../hardware.md#varyings-fragment-programs-and-depth)).
- **GPU fragments and window state:** the fragment backend
  supplies programs and per-draw state for GPU-shaded draws. Window fixtures
  check all eight depth functions, depth write masks, stencil operations,
  two-sided stencil and polygon offset; Z24S8 window configurations are exposed.
  These are selected rendering checks, not complete depth/stencil API qualification
  ([fragment backend](../compiler.md#fragment-backend),
  [GPU contracts](../hardware.md#varyings-fragment-programs-and-depth)).
- **Presentation:** fullscreen SCANOUT windows flip; windowed and covered
  fullscreen frames are copied by the 2D core. X's copy may overlap the next
  frame's raster, while TA and 2D work remain serialized
  ([X11 status](x11.md), [address domains](../hardware.md#memory-and-address-domains)).
  A frame's TA pass also runs beside the previous job's raster
  ([execution](../kernel/execution.md#p3-engine)).
- **Repeated work:** the device suites check changing application frames,
  multiple GL contexts, covering and uncovering a fullscreen client, and client
  exit under load. The [coverage ledger](../../tests/acceptance/README.md#coverage-ledger)
  separately tracks complete acceptance cases and their registered runners.

## Implemented source scope

The checked-in GPU draw path additionally wires blend/mask/logic/alpha and
visibility epilogues, bounded single-level 2D samplers, scissor objects,
positive-Y FBO viewports and target-load draws, flat and smooth varyings,
gl_FrontFacing, depth output, scissored and partial clears with any depth
value, depth/stencil readback, clear-only frames and renders of up to 160
draws. [Graphics](../graphics.md#fragment-state-and-blits)
owns their precise restrictions. These source connections do not extend the
named device results above or qualify the complete feature matrix.

## In progress

- Remove the CPU vertex path; complete shader operations, texture and fragment
  state matrices, render targets/FBOs, queries and truthful caps. Qualify each
  connected state/resource path on the device; host-tested builders alone do
  not establish its rendering behavior.
- Partial renders after parameter-pool exhaustion and MSAA. A second TA OOM
  still loses the device; the [loss policy](../kernel/execution.md#the-loss)
  retains GPU-reachable resources for the boot.
- Complete sharing, resource and display lifetime qualification, clean module
  teardown, suspend/resume and full API/performance selections.
- General numerical qualification of depth, perspective interpolation and raster
  edges remains open. Passing color and depth-function fixtures do not establish
  an exact D24 quantizer or complete numerical precision guarantees.

API readiness has separate [OpenGL 2.1](opengl-21.md) and
[OpenGL ES 2.0](opengl-es-20.md) criteria.

## Progress basis

**Approximate implementation progress: 75%.** The scope is the SGX renderer
from geometry and resource ownership through GPU presentation. Full OpenGL
and GLES qualification has its own [API status](mesa-api.md).

The estimate weights implemented subsystems. Compiler, texture, target and
partial-render code receives partial credit while broader integration and
qualification remain open. That credit does not declare every library feature
usable by ordinary GL applications.
The weights and contributions are engineering estimates, not measured work
hours, remaining time or a fraction of supported API features.

| Implementation block | Weight | Current contribution | Basis and remaining boundary |
| --- | ---: | ---: | --- |
| GPU execution and resources | 25 | 25 | BOs, per-file VM, validated submission, scheduling, IRQs and fences support repeated application work. Complete teardown is counted below. |
| Geometry and vertex pipeline | 20 | 16 | GPU vertex shading, fetch/constants, VBO/IBO, clipping, culling and viewport exist; vertex outputs are kept by location, constant-bound loops unroll and straight-code ifs become selects; FBO viewports and depth ranges are connected. Broader shader/output/primitive coverage and removal of CPU fallback remain open. |
| Fragment compiler and raster state | 25 | 20 | Structured backend, allocation, flow, epilogues and state builders exist. Depth/stencil/offset, blend/mask/logic/alpha, discard, depth output, scissor, flat and smooth varyings and gl_FrontFacing are connected; complete state and numerical qualification remains open. |
| Textures and render targets | 15 | 6 | Layout, twiddle, mip/format conversion and descriptors exist. Bounded single-level 2D sampling and target preservation are connected; wider formats/targets and complete sampling/FBO qualification remain open. |
| Queries, MSAA, large scenes and lifecycle | 10 | 3 | Renders take up to 160 draws; partial-render builders/state model and teardown helpers exist. Partial-render device integration, queries, MSAA and safe unload/suspend remain open. |
| Presentation and applications | 5 | 5 | Flips, GPU copies, covered fullscreen and multiple-context application paths work. |
| **Total** | **100** | **75** | Rounded to the nearest 5% for the README bar. |

The foundations and a substantial part of the remaining library machinery are
implemented. Wider textures/FBOs, state coverage and qualification remain
significant; selected working applications do not complete them.
[Graphics](../graphics.md), [Compiler](../compiler.md),
[native builders](../native-3d.md) and [GPU contracts](../hardware.md) describe
which parts are connected to the product path and which remain host-only.
