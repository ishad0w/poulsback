# Accelerated X11 desktop

<a id="2d-x11"></a>

[Main checklist](../../docs/checklist.md) · [Case metadata](../../spec/dod.json)

This guide qualifies the X11 desktop on the poulsback DDX (`src/xorg`): KMS,
EXA Solid/Copy on the 2D core, Render composition (CPU fallbacks today, EXA Composite on the
3D core planned: [X11 status](../../docs/status/x11.md#in-progress)), DRI3, Present, RandR, DPMS
and Xv. glamor and the stock modesetting DDX are not the product
path; stock modesetting appears only as the ceiling for an x11perf test the
2D core cannot reach (see [release.performance-baselines](release.md#release.performance-baselines)).
Each case names its runner in the metadata, and its concrete cases in
`spec/cases/<case ID>.json`; the [coverage ledger](README.md#coverage-ledger)
counts them.

<a id="2d-x11.backend"></a>

## The DDX and its acceleration paths

<a id="2d-x11.backend-identity"></a>

### 2d-x11.backend-identity

Procedure: Start X11 on the poulsback DDX and capture the loaded modules, DRI3 device and
renderer identities, and the DDX's per-request fallback counters.

Oracle: The active DDX and Mesa are the qualified builds; glamor and shadowfb are not loaded.
Every request EXA declines is counted as a fallback and never labelled accelerated.

<a id="2d-x11.exa-operations"></a>

### 2d-x11.exa-operations

Procedure: Drive each EXA hook (Solid, Copy, Composite, UploadToScreen, DownloadFromScreen,
PrepareAccess) with requests the DDX accepts, beside the DDX's call counters.

Oracle: Each hook's output is exact against the client model, the counters show the hook ran on
its engine, and CPU access waits for the BO's fence.

<a id="2d-x11.core"></a>

## X core rendering requests

<a id="2d-x11.x2d-fixture"></a>

### 2d-x11.x2d-fixture

Procedure: For every [fixture case](../../spec/cases/2d-x11.x2d-fixture.json), reset drawables with
XPutImage, run one X request (copies, fills, stipples, pixmaps, Render, lines),
and read every drawable back.

Oracle: Every pixel of every drawable equals the client's model (the 16 GX functions, planemask,
CopyArea as if through a temporary, clip rectangles); line cases equal the Xvfb CRC list.

<a id="2d-x11.xts5-rendering"></a>

### 2d-x11.xts5-rendering

Procedure: Run the xts5 test purposes of the Xlib rendering sections (Xlib8 GC state, Xlib9
drawing, images and text) on the poulsback DDX.

Oracle: Every test purpose reports PASS. UNTESTED, UNSUPPORTED, NOTINUSE and FAIL are not passes;
a test purpose that does not apply needs an accepted exclusion.

<a id="2d-x11.composite"></a>

## Composition operators, alpha and masks

<a id="2d-x11.composite-operators"></a>

### 2d-x11.composite-operators

Procedure: Run every rendercheck 1.6 test of the [pinned selection](../../spec/cases/2d-x11.composite-operators.json) that composites without a
transform: the single tests, and blend, composite and component-alpha composite once per
Render op.

Oracle: rendercheck's own premultiplied-alpha reference within its tolerance: the test exits 0
and prints no failure. composite, cacomposite and gradients run on ARGB32, XRGB32, A8 and RGB565
(`-f a8r8g8b8,x8r8g8b8,a8,r5g6b5`); every other
test runs on every format the server offers.

<a id="2d-x11.text"></a>

## Text, glyph caching and image upload

<a id="2d-x11.glyph-images"></a>

### 2d-x11.glyph-images

Procedure: Display A8 and component-alpha glyphs through Render, reuse a glyph set after its
glyphs change, draw core text and composite uploaded ARGB images.

Oracle: Independent offscreen references match; cache reuse never shows an older glyph/image and
no pixels outside damage region change.

<a id="2d-x11.transform"></a>

## Scaling, filtering, repeats and transforms

<a id="2d-x11.transforms"></a>

### 2d-x11.transforms

Procedure: Run rendercheck's transformed-coordinate, repeat, gradient and triangle tests.

Oracle: rendercheck's reference within its tolerance: the test exits 0 and prints no failure;
gradients on the four formats above, the others on every format the server offers.

<a id="2d-x11.damage"></a>

## Repaint, scroll, resize and overlapping windows

<a id="2d-x11.desktop-damage"></a>

### 2d-x11.desktop-damage

Procedure: Move/resize/overlap windows, scroll content, change focus and repaint
occluded/damaged regions, with X clients and GL clients in windows.

Oracle: Framebuffer capture agrees with reference scene and frame ID after each synchronized
action; no stale damage, tearing beyond declared presentation mode or wrong occlusion.

<a id="2d-x11.presentation"></a>

## Present and DRI3

<a id="2d-x11.present-order"></a>

### 2d-x11.present-order

Procedure: Exercise the [Present/DRI3 cases](../../spec/cases/2d-x11.present-order.json):
fullscreen flips of numbered bands, cover/uncover transitions, scanline-integrity checks,
a windowed Present copy, and DRI3 Open, PixmapFromBuffers, BuffersFromPixmap and FenceFromFD.
The device client implementing this procedure is not bundled here.

Oracle: Every completion after the first is a flip (copies while covered), the MSC steps by one
for at least 99.5 % of frames, every presented pixmap gets its IdleNotify before it is written
again, and no band or bar is broken. DRI3 buffers round-trip with the same bytes and fences
order a client's render before X reads it.

<a id="2d-x11.output-control"></a>

## Outputs: RandR, DPMS and VT switch

<a id="2d-x11.outputs"></a>

### 2d-x11.outputs

Procedure: Set every mode RandR lists on the Dell's LVDS panel, cycle DPMS and switch VTs with
a GL client running. VGA modes, hotplug and clone/extend layouts are excluded from M1 for now
([exclusions](../../spec/exclusions.json)); they return when a VGA sink is available.

Oracle: Each LVDS mode shows the checked frame at its size; DPMS returns with the same frame; after a VT switch the desktop and the GL client render again,
with no errsite.

<a id="2d-x11.xv"></a>

## Xv textured video

<a id="2d-x11.xv-textured"></a>

### 2d-x11.xv-textured

Procedure: Put planar (YV12, I420) and packed (YUY2, UYVY) images through the Xv adaptor,
scaled up and down, clipped by overlapping windows, through shared memory and on two ports.

Oracle: Every output pixel matches a CPU BT.601 conversion within the frozen per-channel
tolerance; the adaptor advertises only what it renders.

<a id="2d-x11.device-lost"></a>

## A device lost with X running

<a id="2d-x11.device-lost-desktop"></a>

### 2d-x11.device-lost-desktop

Procedure: Wedge the engine with X and a GL client running (the
[device-loss policy](../../docs/kernel/execution.md#the-loss)).

Oracle: X keeps an unaccelerated desktop until the reboot, the GL client gets an error rather
than a hang, HOLD resources are not released, and the reboot brings the accelerated desktop
back.

<a id="2d-x11.server"></a>

## The rest of the X server

<a id="2d-x11.server-features"></a>

### 2d-x11.server-features

Procedure: Check the cursor, a RandR gamma ramp, the colour maps of the visuals the DDX offers,
xfwm4's compositor over the Composite extension (with a GL client, and a fullscreen one that
unredirects) and server regeneration after the last client exits.
`GLX_EXT_texture_from_pixmap`, which a GL compositor needs, is a
[GLX case](gl21.md#gl21.glx-tfp).

Oracle: Each case's own criterion in `spec/cases/2d-x11.server-features.json`; a feature the DDX
does not offer needs an accepted exclusion and is then refused cleanly, never faked.

<a id="2d-x11.desktop-stress"></a>

## One hour of real desktop

<a id="2d-x11.desktop-long"></a>

### 2d-x11.desktop-long

Procedure: Run a scripted XFCE session at 1280×800 for one hour: terminal scrolling, file
manager, text editor, window moves and a GL client.

Oracle: Correctness checks, resource accounting and shared kernel-health gates hold;
GPU/fallback coverage is separately tabulated.
